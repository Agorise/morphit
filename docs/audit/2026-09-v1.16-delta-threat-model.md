# Morphit threat-model — v1.16 delta addendum (2026-09)

Extends the 2026-05 STRIDE matrix / attack-tree / red-team narrative to the
architecture that shipped after them: the **on-chain federation directory +
probe**, **hidden-only clearnet elimination**, **hidden transport (Tor/I2P)**,
the **federated price feed**, the **kubo IPFS release gateway**, and the
**contact-protocol** surface. Mitigations here were verified in the code during
the v1.16.x delta deep-deep (`AUDIT-v1.16.x-DELTA-DEEP-DEEP.md`); this doc frames
them as threats so the reasoning is reusable.

Status: 🟢 mitigated · 🟡 mitigated with residual · ⚠️ open

---

## Spoofing

### S5 — Hostile peer spoofs a federation identity (fee redirection) 🟢
**Threat:** a rogue instance advertises another operator's relay/treasury to
redirect signup fees or impersonate a trusted node in the directory.
**Mitigations (federation probe):** operator==relay identity check with the
both-reserved waiver (cp775 — reserved names can only be held by their owner);
treasury baseline withheld until the prober is synced (cp768, no false mismatch);
unparseable `/v1/instance` → `unreachable`, not a fee-redirection accusation
(cp770); shared-relay-account collision alert (cp777, OPERATIONS §29).
**Residual:** peer hidden addresses live only in `/v1/instance`, not on-chain, so
a tor-only node has no Tor-native path to a clearnet peer (cp770 architectural
gap — tracked, low priority while the directory is small).

### S6 — contact_url userinfo phishing 🟢 (audit v16-2, fixed)
**Threat:** a malicious operator registers `https://matrix.to@evil.com` so the
directory's "Contact this operator" link looks like a trusted host but navigates
victims to `evil.com`.
**Mitigation:** userinfo rejected at the on-chain gate (O1.2) AND, as of the v16-2
fix, in the shared `detectContactProtocol` + `safeContactUrl`, so all four
consumers enforce it. Scheme allowlist blocks javascript:/data:/etc.; host-label
regexes are anchored (no `t.me.evil.com` spoof).

### S7 — Hostile peer skews the federated price 🟡
**Threat:** on a hidden-only node the price is a median of peers' `morphit_native`
observations; a Sybil set of peers could push the median to mis-price orders.
**Mitigations:** median (not mean) resists a minority; `minObservations: 3` +
240-min freshness window; plausibleMin/Max bounds + static floor clamp;
disagreement monitor + `PREFER_NATIVE_WHEN_DISAGREEING`; own-native blended in.
**Residual:** a majority-Sybil federation could still move the median within the
plausible band. Bounded by the plausibility clamp; accepted while the federation
is small + operator-curated. Revisit as the directory grows (peer reputation /
weighting).

## Tampering

### T5 — Tampered release served over a peer's IPFS gateway 🟢
**Threat:** a hidden-only node fetches its upgrade from a peer's `.onion` IPFS
gateway; a malicious peer serves a trojaned tarball.
**Mitigation:** the fetched tarball is verified against the **on-chain SHA-256**
before use; mismatch → fail-closed (`return 5`, stay on current version), never a
clearnet-mirror fallback. Content addressing (CID) is self-verifying. The kubo
gateway serving it runs `NoFetch=true` (serves only its own pinned release).

## Information disclosure

### I6 — Clearnet IP leak from a node that claims to be hidden-only 🟢
**Threat:** a censored/at-risk operator (e.g. Iran) believes they're hidden-only
but an outbound leg silently uses clearnet, leaking their real IP.
**Mitigations (verified Phase 1):** `clearnet_eliminated` is a strict fail-closed
AND of seven legs; chain reads gate on an empty clearnet RPC pool (Zod honors
explicit-empty → `[]`); price drops **all** clearnet upstreams on hidden-only
(factory.ts); upgrades fail-closed over Tor/I2P; SOCKS5 uses ATYP=domain so
`.onion` is never resolved locally (no DNS leak). Transport legs now validate the
advertised address format (audit v16-1).
**Residual:** the "zero clearnet" claim is a self-posture flag; an operator can
still run auxiliary clearnet software outside Morphit's control. The flag speaks
only to Morphit's own outbound legs (documented).

### I7 — kubo gateway as a data/dedup oracle 🟢
**Threat:** an exposed gateway reveals what the node has pinned, or is abused to
probe arbitrary IPFS content.
**Mitigation:** `NoFetch=true` → only this node's own (already public) pinned
release is served; any other CID 404s. Admin API (5001) stays loopback even when
the gateway is exposed. Nothing private is pinned.

## Denial of service

### D6 — kubo gateway bandwidth abuse 🟡
**Threat:** an exposed `/ipfs` endpoint is hammered to exhaust bandwidth.
**Mitigations:** behind BunkerWeb rate-limits + per-IP `limit_conn` (attack-
resilience batch); `NoFetch` makes each request a cheap pinned-lookup-or-404;
exposure is opt-in (default loopback, `/ipfs` inert). **Residual:** bandwidth for
the ~12 MB release if heavily fetched; acceptable for a release mirror.

## Elevation of privilege

### E-delta — exposed gateway → pin/config control 🟢
**Threat:** reaching the exposed read gateway is leveraged into pin/unpin/config.
**Mitigation:** the expose toggle rewrites only `Addresses.Gateway`;
`Addresses.API` (5001, the write surface) is unconditionally loopback. No path
from the read gateway to control.

## Attack-tree — new branches

- **Goal: leak a hidden-only operator's real IP.**
  - via chain RPC over clearnet → blocked (empty pool, combined-pool invariant)
  - via price API over clearnet → blocked (all clearnet upstreams dropped)
  - via upgrade over a clearnet mirror → blocked (fail-closed `return 5`)
  - via local DNS lookup of a `.onion` → blocked (SOCKS5 ATYP=domain)
  - via a clearnet Matrix homeserver → blocked (`matrixClean` leg)
  - **⇒ every leaf mitigated; the strict-AND gate keeps the claim off if any is unproven.**
- **Goal: redirect signup fees.** operator/relay spoof → identity + reserved-name
  + treasury + shared-relay checks (S5). Leaves mitigated.
- **Goal: phish a directory user.** contact_url userinfo / bad scheme / spoofed
  host-label → all closed (S6). Leaves mitigated.
- **Goal: serve a trojaned upgrade.** peer IPFS gateway → on-chain SHA verify,
  fail-closed (T5). Leaf mitigated.

## Red-team narrative — "the hostile federation peer"

A rogue operator joins the directory and tries, in order: (1) advertise
`@morphit`'s relay to skim fees — rejected by the identity/reserved checks and
surfaced as a shared-relay alert; (2) serve a trojaned release over their onion
IPFS gateway to a censored peer mid-upgrade — the on-chain SHA mismatch
fail-closes the victim rather than installing it; (3) flood the federation with
Sybil price observations — moved the median only within the plausibility band,
clamped by the static floor and flagged by the disagreement monitor; (4) register
a `matrix.to@evil.com` contact link — rejected before it ever reaches the
directory. No step yields fee theft, IP disclosure, code execution, or a
convincing phish. The residuals (majority-Sybil price drift within band; no
Tor-native path to a clearnet peer) are documented and bounded, not open holes.
